# CLAUDE.md — правила для агента

## Окружение

- Пользователь: `agent`, без sudo. Работай только внутри `/home/agent`.
- Docker: rootless, сокет `unix:///run/user/$(id -u)/docker.sock` (`DOCKER_HOST` уже задан).
- Python ставь через `uv`, Node через `fnm`. Ничего не ставь глобально в систему.
- На сервере работает VPN владельца (порты 22, 80, 443 и др.). Не трогай их и не пытайся занять.

## Порты

- Тебе выделен диапазон 9000–9099/tcp. Наружу публикуй только эти порты.
- Внутренние сервисы (БД, Redis и т.п.) не публикуй наружу: используй docker network или `127.0.0.1:<порт>`.
- Перед использованием порта проверь, что он свободен: `ss -tlnp | grep :90`.
- Порты записывай в `PORTS.md` в корне проекта: порт → сервис.

## Задача

Написать Python-агента, который работает с:

1. Telegram: бот на `aiogram` 3.x, по умолчанию polling (без входящих портов).
2. Яндекс Документы / Диск: через официальный REST API, OAuth-токен из `.env`.
3. Docker: сервис сам разворачивается через `docker compose` (rootless).

## Стек и стиль

- Python 3.12+, `uv`, `pydantic` / `pydantic-settings` для конфига, асинхронный код (`asyncio`, `httpx`).
- Структура:

  ```
  ~/projects/<name>/
    src/<name>/        # код
    tests/             # pytest
    docker-compose.yml
    Dockerfile
    .env.example       # пример без секретов
    README.md
    PORTS.md
  ```

- Тесты: `pytest` + `pytest-asyncio`. Внешние API (Telegram, Яндекс, GigaChat) в тестах мокай.
- Разработка по TDD: сначала падающий тест (red), затем минимальная реализация (green),
  затем рефакторинг. Тест и реализацию можно коммитить вместе, но тест пишется первым.
- Пока владелец не выдал API-ключи, всё разрабатывается и проверяется локально на моках.
- Линтер и форматтер: `ruff`. Типы: аннотации везде.
- Коммить в git маленькими осмысленными шагами.

## Секреты

- Токены хранятся только в `.env` (`chmod 600`). `.env` добавь в `.gitignore`.
- Никогда не выводи токены в логи, коммиты, README или ответы.
- В контейнеры передавай секреты через `env_file`, не вшивай их в образ.

## Docker

- Только `docker compose` из папки проекта.
- Обязательно `restart: unless-stopped`, лимиты `mem_limit` / `cpus`, healthcheck для долгоживущих сервисов.
- Не используй `privileged`, `network_mode: host` и монтирование `/`, `/var/run`, `/etc`.
- Чисти за собой: `docker image prune` после экспериментов.

## Запрещено

- `sudo`, `su`, изменение системных файлов, `systemctl` (кроме `systemctl --user`).
- Чтение чужих домашних папок и `/root`.
- Изменение файрвола, SSH и настроек VPN.
- Сканирование сети и подключение к сторонним серверам, кроме Telegram API, Яндекс API, GigaChat API (`ngw.devices.sberbank.ru`, `gigachat.devices.sberbank.ru`), PyPI, GitHub и Docker Hub.
- Удаление данных вне `~/projects`.

## Порядок работы

1. Перед крупным изменением коротко опиши план.
2. Если не хватает прав или токена, остановись и спроси владельца, не обходи ограничения.
3. После изменений запусти `ruff check`, `pytest` и `docker compose up -d --build`, проверь логи.
4. Обновляй `README.md`: как запустить, какие переменные нужны, какие порты заняты.
